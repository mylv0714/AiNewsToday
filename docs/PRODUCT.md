# Morning Brief — 제품 기획

커피를 내리는 동안 어제 밤 세상을 한 번 훑고, 첫 모금을 마실 때쯤엔 “오늘은 이거면 충분하다”고 느끼게 만드는 개인용 아침 페이지.

이 문서는 구현 전에 **무엇을 만들지, 무엇을 절대 만들지 않을지**를 고정한다. 구현 프롬프트는 `prompts/IMPLEMENT.md`, 매일 에디션을 쓰는 편집 프롬프트는 `prompts/MORNING_EDITOR.md`.

---

## 1. 왜 이 제품인가

AI 뉴스는 이미 많다. 뉴스레터, 트위터, HN, 유튜브, Discord. 문제는 정보가 부족한 게 아니라 **아침 15분을 망친다**는 것이다.

- 피드형 제품은 끝이 없다. 커피가 식도록 스크롤한다.
- 뉴스레터는 메일함에서 다른 일과 섞인다. “나중에”가 된다.
- 원문은 영어, 제목은 과장, 같은 사건이 일곱 번 복제된다.
- 한국 아침(KST) 기준으로는 미국 저녁~심야가 “어젯밤”인데, 대부분의 피드는 그 시차를  Ignor 한다.

이 제품의 일은 뉴스를 더 모으는 것이 아니다. **오늘의 유한한 판(edition)을 닫아서 내놓는 것**이다.

비유는 대시보드가 아니라 **조간신문 한 부**. 날짜가 찍혀 있고, 면수가 정해져 있고, 다 읽으면 끝이다.

---

## 2. 누가, 언제, 어떻게 쓰는가

### 사용자

본인. 혼자 쓰는 개인 의식(ritual) 도구. 소셜, 댓글, 구독 전환, 알림은 없다.

가정하는 독자상:

- AI를 일로 다루거나, 적어도 흐름을 놓치고 싶지 않은 사람
- 영어 원문을 읽을 수 있지만, 아침에 그걸 다 열고 싶지는 않은 사람
- 모델 릴리스, 논문, GitHub, 랩 공식 발표를 한 화면에서 보고 싶은 사람

### 의식의 흐름 (목표 UX)

1. 06:30–09:00, 커피를 내린다.
2. 북마크 하나, 또는 `localhost` / 고정 URL 하나를 연다.
3. 오늘 날짜와 **오늘 한 줄**이 먼저 보인다.
4. 8–12분 안에 판을 다 읽는다. 더 읽고 싶으면 원문 링크만 따른다.
5. 창을 닫는다. 하루를 시작한다.

성공의 정의는 “더 많은 뉴스”가 아니다. **창을 닫는 데 죄책감이 없는 것**.

### 시간대

기준 시간대는 **Asia/Seoul**. “어젯밤”은 미국 업무일 오후~밤, 유럽 저녁, arXiv 일일 발표가 한국 심야~새벽에 떨어지는 구간에 해당한다.

매일 생성 시각 제안: **KST 06:15**. 커피 전에 판이 이미 나와 있어야 한다. 생성 이후 페이지는 **그날의 판으로 동결**한다. 읽는 도중에 헤드라인이 바뀌지 않는다.

## 3. 편집 원칙 (제품의 핵심)

이 제품의 차별점은 UI가 아니라 **편집 태도**다.

### 3.1 유한하다

한 판의 분량은 커피 한 잔. 목표 독서 시간 **8–12분**, 절대 상한 **15분**.  
히어로 1, 브리핑 5–7, 모델/도구 3–5, 논문 3, GitHub 3, 여유 있으면 읽을 거리 1. 이 숫자를 넘기면 실패한 판이다.

### 3.2 중복을 하나로

같은 모델 출시가 트위터, HN, 블로그, 유튜브에 동시에 뜨면 **사건 하나**다. 클러스터링한 뒤 가장 신뢰할 수 있는 원문 하나를 본링크로, 나머지는 “같은 이야기”로 접는다.

### 3.3 과장하지 않는다

금지 어휘의 기본 목록: 혁신적, 판을 갈다, game-changing, 충격, 마침내, must-read.  
사실 유형을 밝힌다: **공식 발표 / 논문 / 제품 출시 / 루머 / 해석**. 루머는 루머라고 쓴다.

### 3.4 아침에 쓸모 있는 것만

아침에 필요한 질문:

1. 내가 오늘 일하면서 전제가 바뀌는가? (새 모델, API, 정책, 가격)
2. 주말에 깊게 파고 싶을 씨앗이 있는가? (논문, repo)
3. 업계 공기가 바뀌었는가? (큰 규제, 큰 사고, 큰 거래)

펀딩 소문, 인플루언서 리캡, “X vs Y 10선”, 채용 공고, 밈은 기본 제외.

### 3.5 한국어로 먼저, 원문은 뒤에

본문은 **한국어**. 고유명사·모델명·논문 제목은 원문 유지.  
문장은 존댓말도 반말도 아닌 **담백한 평서체**. 잘 아는 동료가 옆자리에서 짧게 브리핑하는 톤. 앵커가 아니고, 조간 해설도 과하지 않다.

### 3.6  Sufficiency (“오늘 이 정도면 됐다”)

페이지 하단에 명시한다: 이 판은 여기까지다. 더 읽고 싶으면 원문.  
무한스크롤, “관련 추천 20”, 실시간 티커, 푸시 알림은 만들지 않는다.

## 4. 매일의 판 — 정보 구조

한 화면, 한 스크롤. 네비게이션은 날짜와 아카이브뿐이다.

```
┌─────────────────────────────────────────┐
│  2026년 9월 2일 수요일 · 8분 판          │
│  오늘 한 줄: (한 문장)                    │
├─────────────────────────────────────────┤
│  1. 히어로                               │
│     오늘 가장 중요한 사건 하나            │
│     왜 중요한지 3–5문장 + 원문 1개        │
├─────────────────────────────────────────┤
│  2. 당신이 자는 동안                     │
│     불릿 5–7개. 한 줄 + 한 줄 해설        │
├─────────────────────────────────────────┤
│  3. 모델 · 도구                          │
│     출시/업데이트 3–5. 한 줄에 무엇이 바뀌었는지 │
├─────────────────────────────────────────┤
│  4. 논문 세 편                           │
│     제목, 한 문장 의미, 왜 지금인지        │
├─────────────────────────────────────────┤
│  5. GitHub                               │
│     별이 갑자기 붙은 저장소 3개            │
│     무엇을 하는 코드인지 한 줄             │
├─────────────────────────────────────────┤
│  6. 커피가 남았다면                      │
│     긴글 하나. 안 읽어도 되는 것이 기본    │
├─────────────────────────────────────────┤
│  이 판은 여기까지 · 어제 판 보기           │
└─────────────────────────────────────────┘
```

### 섹션 규칙

| 섹션 | 목적 | 비어 있을 때 |
|------|------|----------------|
| 오늘 한 줄 | 창을 열자마자 오늘을 한 문장으로 고정 | 억지로 만들지 말고 “조용한 밤이었다” |
| 히어로 | 하나만 깊게 | 히어로급이 없으면 섹션을 빼고 브리핑을 두껍게 |
| 자는 동안 | 시차 보정 브리핑 | 최소 3개. 없으면 생성 파이프라인이 빈 것 |
| 모델·도구 | 실무 전제 변경 | 없으면 섹션 숨김 |
| 논문 | 씨앗. 읽으라는 뜻이 아님 | arXiv 노이즈면 과감히 2개, 1개도 가능 |
| GitHub | 손과 가까운 신호 | 별만 많고 실체가 없으면 제외 |
| 커피가 남았다면 | 선택적 심화 | 없으면 섹션 숨김. 채우려고 광고성 글을 올리지 않음 |

카드 하나당 필수 필드:

- `title` (한국어 헤드라인, 원문 제목 직역 금지 — 의미를 다시 씀)
- `kind`: `announcement | paper | release | repo | analysis | rumor`
- `why_now` (지금 아침의 이유, 1문장)
- `source_name`, `canonical_url`
- `published_at` (원문 시각, 표시는 상대 + KST)
- `reading_seconds` (예상)

## 5. 소스와 신뢰

수집은 넓게, 게재는 좁게. 파이프라인은 50–150건을 모아 **8–20건의 클러스터**로 줄인 다음, 위 구조에 끼워 넣는다.

### 1티어 — 거의 항상 신뢰

- 랩·회사 공식: OpenAI, Anthropic, Google DeepMind, Meta AI, xAI, Mistral, Cohere
- 모델 허브: Hugging Face (새  palettes가 아니라 **의미 있는  palettes** — 다운로드/토론 급증)
- arXiv: `cs.LG`, `cs.CL`, `cs.AI`, `cs.CV` 일일 리스트. 게재 ≠ 중요.
- GitHub: AI 관련 저장소의 **별 속도**, 릴리스 노트, README가 실체인 것

### 2티어 — 맥락용

- Hacker News (Algolia). 점수와 댓글 수보다 “이 토론이 실무에 영향 있나”
- 품질 있는 테크 저널리즘: 확인된 보도. 제목의 형용사 제거 후 사실만
- 소수 큐레이션 뉴스레터는 **원소스가 아닐 때만** 힌트로. 본링크로 쓰지 않음

### 3티어 — 기본 제외, 예외만

- Reddit, X/Twitter, 유튜브 썸네일 타이틀
- 예외: 원저자가 직접 쓴 스레드이고 1·2티어에 아직 없는 1차 발표

### 수집 시 명시적으로 버리는 것

- 동일 사건의 N번째 요약 뉴스레터
- “내가 써본 프롬프트 50”
- 코인·에이전트 토큰 가격
- 벤치마크 스크린샷만 있는 자화자찬 스레드
- 채용, 이벤트 홍보, 웨비나

## 6. 랭킹 — 기계가 고르고, 편집자가 자른다

점수 함수는 단순해야 한다. 복잡한 개인화는 MVP에 넣지 않는다.

```
score =
    importance × 3     # 업계 전제를 바꾸는가 (0–3)
  + novelty × 2        # 지난 24h에 새로워졌는가 (0–2)
  + actionability × 2  # 오늘 손이 가는가: API, 가중치, repo (0–2)
  + source_tier        # 1티어 +2, 2티어 +1, 3티어 0
  − hype_penalty       # 제목 과장, 복제 보도 −1~−3
```

동점일 때 우선순위: **공식 발표 > 릴리스 > 논문+코드 > 논문만 > 해석 기사**.

클러스터 대표 문서는 다음 순으로 고른다.

1. 공식 블로그/docs
2. GitHub Release / README
3. 논문 PDF / abs 페이지
4. 확인된 언론 보도
5. 그 외

LLM의 역할은 점수를 발명하는 것이 아니라:

- 중복 묶기
- 한국어 헤드라인·한 줄 해설 쓰기
- 히어로 선정 이유 한 단락
- “조용한 밤”인지 판단
- 과장 표현 제거

LLM이 없는 날에도 **원제 + 링크 + 소스 목록**만이라도 판이 나와야 한다. 요약 실패가 아침을 비우면 안 된다.

## 7. 톤과 카피

### 보이스

- 짧다. 한 문장이 두 줄 넘어가면 나눈다.
- 주어를 명확히. “것이 밝혀졌다” 같은 수동태를 피한다.
- 숫자는 남긴다. 파라미터, 가격, 맥락 길이, 별 증가.
- 모르는 것은 “원문에 없다”고 쓴다. 추측으로 메우지 않는다.

### 페이지에 고정할 카피

- 상단: `{날짜} · {N}분 판`
- 히어로 위: `오늘`
- 브리핑 위: `당신이 자는 동안`
- 하단: `이 판은 여기까지입니다. 창을 닫아도 됩니다.`
- 소스가 빈약할 때: `오늘은 큰 움직임이 적었습니다. 억지로 채우지 않았습니다.`

### 언어 처리

- 모델명, 논문 제목, 회사명, repo명: 원문
- 일반 명사: 한국어 (`가중치`, `추론`, `컨텍스트 길이`)
- 원문 인용 1문장까지. 그 이상은 링크로

## 8. 시각 — 조간이 아니라 카페 테이블

기술 콘솔처럼 보이지 않는다. 다크 터미널, 네온 그린, 사이버펑크는 반대편이다.

### 분위기

- 종이, 잉크, 따뜻한 조명
- 날짜가 가장 큰 글자
- 본문은 한 열, 최대 너비 약 680px. 잡지는 두 열이 멋있지만 아침엔 한 열이 빠르다
- 여백을 아껴 카드를 때려 넣지 않는다. 섹션 사이는 숨 쉴 간격

### 색 (라이트 / 새벽)

라이트(기본, 해가 있는 아침):

- 종이 `#F4EFE6`
- 잉크 `#1C1916`
- 약한 잉크 `#6B645C`
- 액센트는 색이 아니라 **무게**: 히어로 제목만 크게

새벽(선택, 6시의 어두운 부엌):

- 종이 `#1A1816`
- 잉크 `#E7E0D6`
- 파란빛 최소. OLED 블랙보다 약간 갈 것

### 타이포

- 한글 본문: Pretendard 또는 고품질 산세리프
- 날짜/히어로: 세리프 하나 (Source Serif, Newsreader 계열). 한글 히어로는 본명조가 있으면 최선, 없으면 Pretendard 큰 무게
- 메타(소스, 시각, kind): 작은 대문자 느낌의 캡션
- 코드/repo명: 모노스페이스 한 종류만

### 움직임

거의 없다. 페이드 200ms 이하면 충분. 라이브 카운터, 마퀴, 스켈레톤 남용 없음.  
첫 페인트에 **날짜와 오늘 한 줄**이 이미 있어야 한다.

### 하지 말 것

- 햄버거 메뉴에 숨긴 다섯 개 페이지
- 히어로 캐러셀
- 로고 애니메이션
- 광고 유닛이 들어올 자리
- “Trending now” 빨간 배지

## 9. 기술 방향

목표는 매일 아침 **깨지지 않는 정적 판**이다. 인터랙티브 앱이 아니다.

### 권장 형태

```
수집기 (cron)
  → 정규화/중복제거
    → 편집 LLM (MORNING_EDITOR)
      → edition JSON
        → 정적 페이지 렌더
          → 호스팅
```

- **앱 프레임워크**: Astro 또는 Next.js(정적 export). 아침 페이지에 클라이언트 JS는 테마 토글 정도면 충분.
- **데이터**: 하루 하나의 `editions/YYYY-MM-DD.json`. 이 파일이 곧 아카이브.
- **스케줄**: GitHub Actions, cron `15 21 * * *` UTC = KST 06:15.
- **호스팅**: GitHub Pages 또는 Vercel. 개인용이면 Pages로 충분.
- **LLM**: 환경변수 API 키. 실패 시 템플릿 폴백 판.
- **수집**: RSS + HN Algolia + arXiv API + GitHub Search/Releases. 스크래핑은 최후.

### MVP에 넣지 않는 것

- 계정, OAuth, DB
- 개인화 피드, 키워드 알림
- 댓글, 하이라이트 공유
- 모바일 앱
- 멀티 유저
- 실시간 웹소켓
- 검색 (아카이브가 쌓인 다음)

### MVP 범위

1. 매일 06:15 KST에 판 생성
2. `/` 는 오늘 판, `/archive/YYYY-MM-DD` 는 과거 판
3. 라이트/새벽 테마
4. 원문 새 탭
5. LLM 요약 + 소스 폴백
6. 로컬에서 `npm run digest` 로 수동 재생성 가능

### 그 다음 (MVP 이후)

## 10. 품질 기준 — 이 판이 좋은가

출하 전에 이 질문으로 자른다.

1. 커피가 식기 전에 끝나는가?
2. 창을 열자마자 오늘이 한 문장으로 잡히는가?
3. 같은 사건이 두 번 나오는가? 나오면 실패.
4. 히어로가 “진짜 히어로”인가, 아니면 빈칸 메우기인가?
5. 한국어가 번역투인가? (`~가 발표되었습니다`의 연속이면 다시 씀)
6. 링크가 죽은가, 로그인 벽인가?
7. 아무 일도 없던 날을 사건처럼 포장했는가?
8. GitHub 항목을 실행 파일처럼 설명했는가, 별 숫자만 적었는가?

## 11. 프로젝트 이름

저장소는 `GithubNews`다. 제품 对外 이름은 조금 더 아침다워야 한다.

후보:

- **Morning Brief** — 직설. 기본 추천.
- **조간** — 한글 한 단어. 도메인이 어려울 수 있음.
- **Coffee Edition** — 의식은 잘 담기나 가벼움.
- **Overnight** — “자는 동안”에 정확.

코드네임은 `brief`. 페이지 타이틀: `Morning Brief · 2026.09.02`.

GitHub을 소스의 한 축으로 두되, 제품 전체를 “깃허브 뉴스”로 포장하지 않는다. 깃허브는 손의 신호고, 히어로는 대개 모델·랩·논문이다.
